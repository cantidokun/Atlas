============================================================
1. PROJECT
============================================================

Atlas is a local Blender environment-acquisition agent.

Core architecture:

User task
    ↓
Python orchestrator
    ↓
Local Qwen/Ollama model
    ↓
Reasoning and evidence selection
    ↓
Blender tools
    ↓
Evidence ledger
    ↓
Python controller when an authorized action is required
    ↓
Independent verification
    ↓
Final-answer validation or deterministic finalization

Core principle:

Qwen handles reasoning and interpretation.
Python handles execution, state, mandatory actions, verification,
and completion control.

============================================================
5. CURRENT CONTROLLER COMPONENTS
============================================================

controller_state.py
- Tracks BEFORE, TARGET, WRITE, AFTER, and COMPLETE.
- Calculates target positions from measured evidence.

controller_runtime.py
- Executes exactly one mandatory controller action at a time.
- Does not delegate mandatory action ordering to Qwen.

controller_bridge.py
- Connects controller state to the existing agent.
- Hydrates BEFORE state from existing evidence.

controller_execution_adapter.py
- Mirrors controller-owned results into normal tool history and evidence.

controller_integration.py
- Provides the integration boundary between the agent and controller.

run_agent_with_controller.py
- Live compatibility entrypoint.
- Inserts controller ownership into the existing Qwen loop without
  rewriting the main agent.

controller_finalization.py
- Builds a deterministic final report from verified evidence.

============================================================
6. GENERAL ACTION PLANNING V1
============================================================

A generic module exists:

action_plan.py

It defines:

ActionSpec
- One ordered authorized action.

ActionPlan
- Tracks the current action index.
- Exposes the next action.
- Records successful results.
- Blocks on required failures.
- Reports completion state.
- Produces a serializable snapshot for logging/evidence.

This is intentionally separate from the goalpost controller.

14. NEXT DEVELOPMENT TARGET
============================================================

The next target is conditional action planning.

Atlas must determine from authoritative evidence whether the requested
state is already satisfied before executing a proposed write.

Desired behavior:

Task
 ↓
Structured evidence requirements
 ↓
Evidence ledger
 ↓
Determine whether target already holds
 ↓
If already satisfied: skip unnecessary writes
 ↓
If not satisfied: retain authorized action plan
 ↓
Python-controlled execution
 ↓
Independent verification
 ↓
Completion

The first test should use the existing goalpost fixture in an already-correct
state and prove that Atlas does not write unnecessarily.

A second test should use a genuinely incorrect state and prove that the
necessary write path remains available.

============================================================

Do not add tools without proving a real capability gap.

Do not let a successful Blender state depend on a perfect Qwen final answer.

Do not allow an action plan to execute without explicit authorization.

Preserve working components and improve incrementally.

Keep README.md, ATLAS_HANDOFF_CONTEXT.txt, and DEVELOPMENT_LOG.md synchronized
with verified milestones and test results.
