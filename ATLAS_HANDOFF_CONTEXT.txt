============================================================
1. PROJECT
============================================================

Atlas is an AI-assisted sports virtual production and digital-twin platform.

Blender is the first proven execution environment. Unreal Engine is a planned
complementary production environment. The long-term goal is a production suite
in which specialized AI agents can understand captured sports footage, reason
about environments and assets, plan production changes, execute operations,
and independently verify the resulting state.

Atlas is intended to span:

- sports capture and analysis
- digital twins and spatial understanding
- AI-assisted virtual production
- Blender scene construction and manipulation
- Unreal Engine real-time production workflows
- cinematic sports effects and environmental treatments
- production automation and orchestration

Core architecture:

Sports footage / production task
    ↓
Atlas task understanding
    ↓
Evidence and scene reasoning
    ↓
Specialized production agents
    ↓
Blender / Unreal / future tools
    ↓
Production state
    ↓
Independent verification
    ↓
Finished production result

Core control principle:

Qwen/AI agents handle reasoning and interpretation.
Python handles execution, authorization, state, mandatory actions,
verification, and completion control.

4. CURRENT CONTROLLER COMPONENTS
============================================================

controller_state.py
- Tracks BEFORE, TARGET, WRITE, AFTER, and COMPLETE.
- Calculates target positions from measured evidence.

controller_runtime.py
- Executes exactly one mandatory controller action at a time.
- Does not delegate mandatory ordering to Qwen.

controller_bridge.py
- Connects controller state to the existing agent.
- Hydrates BEFORE state from existing evidence.

controller_execution_adapter.py
- Mirrors controller-owned results into normal tool history and evidence.

controller_integration.py
- Integration boundary between the agent and controller.

run_agent_with_controller.py
- Live compatibility entrypoint.

controller_finalization.py
- Builds a deterministic final report from verified evidence.

13. NEXT DEVELOPMENT TARGET
============================================================

Conditional action planning.

Atlas must determine from authoritative evidence whether the requested state
is already satisfied before executing a proposed write.

Desired behavior:

Task
 ↓
Structured evidence requirements
 ↓
Evidence ledger
 ↓
Determine whether target already holds
 ↓
Already satisfied? → skip write
 ↓
Not satisfied? → retain authorized action plan
 ↓
Python-controlled execution
 ↓
Independent verification
 ↓
Completion

Two tests are required:

1. Already-correct state:
   prove Atlas performs no unnecessary write.

2. Incorrect state:
   prove the necessary authorized write path still works.

Before either test, malformed tool arguments must be rejected at the planning
boundary rather than being passed to Blender tools.

17. DEVELOPMENT RULES
============================================================

Do not rewrite the entire agent.
Do not remove the evidence ledger.
Do not remove independent post-write verification.
Do not make goalpost behavior the generic architecture.
Do not add tools without proving a real capability gap.
Do not let a successful production state depend on a perfect Qwen final answer.
Do not allow an action plan to execute without explicit authorization.
Keep Blender- and Unreal-specific logic behind appropriate boundaries.
Preserve working components and improve incrementally.
Keep README.md, ATLAS_HANDOFF_CONTEXT.txt, and DEVELOPMENT_LOG.md synchronized.

18. HANDOFF SUMMARY
============================================================

Atlas has proven the controlled modification loop in the real Blender
environment and the first live Qwen structured planning boundary.

The project is moving from:

"Can Python reliably control one known modification?"

to:

"Can Atlas reliably control authorized production plans generated from task
requirements and evidence, while avoiding unnecessary writes and eventually
coordinating multiple production environments?"

Core principle remains:

Reason with Qwen.
Control with Python.
Measure with production tools.
Verify independently.

The broader product direction is an AI-assisted sports production suite,
with Blender as the current proven environment and Unreal Engine agents as a
planned next production layer.
