1. PROJECT
============================================================

Atlas is a local Blender environment-acquisition agent.

Core architecture:

User task
    ↓
Python orchestrator
    ↓
Local Qwen/Ollama model
    ↓
Reasoning and evidence selection
    ↓
Blender tools
    ↓
Evidence ledger
    ↓
Controller when an authorized action is required
    ↓
Independent verification
    ↓
Final-answer validation / deterministic controller finalization

Core principle:

Qwen handles reasoning and interpretation.
Python handles execution, state, mandatory actions, verification,
and final-answer control.

============================================================
9. LIVE FAILURE THAT WAS FOUND
============================================================

The Blender modification itself succeeded.

The failure happened during final-answer generation.

Qwen first produced an answer that omitted required temporal evidence:

- initial measured positions
- initial midpoint
- target positions
- positional adjustment
- final verified state

The Python validator correctly rejected the incomplete answer.

Qwen then requested another relationship inspection even though the
required final evidence was already available.

The final inspection returned the correct state, but Qwen reached the
maximum reasoning-step limit before producing an accepted final answer.

Important conclusion:

This was NOT a Blender write failure.

This was NOT a controller movement failure.

This was a final-answer recovery problem.


============================================================
10. FINALIZATION FIX — IMPLEMENTED
============================================================

A new module was added:

controller_finalization.py

Purpose:

When a controller-owned midpoint modification is complete and the
independent final inspection proves the required state, Python can build
a complete state-aware final report directly from the evidence ledger.

The report contains:

- INITIAL MEASURED STATE
- CALCULATED TARGET STATE
- positional adjustment
- FINAL VERIFIED STATE
- final relationship facts

This is a recovery path for controller-owned tasks.

Normal non-controller tasks still use the normal Qwen final-answer
validation path.

A regression test file was added:

test_controller_finalization.py

The controller entrypoint was also updated so that a completed
controller task uses this deterministic finalization path instead of
spending another Qwen reasoning cycle.

============================================================
17. GENERAL EVIDENCE PLANNER
============================================================

General Evidence Planner V1 is still in progress.

Current principle:

1. Identify the evidence needed by the current task.
2. Check the evidence ledger.
3. If the evidence is already known, do not repeat the tool.
4. If it is missing and an existing tool can obtain it, acquire it.
5. If no existing tool can obtain it, identify the actual capability gap.
6. Only then consider adding a new tool.

The current goalpost controller must NOT become a permanent goalpost-
specific workflow.

22. CORE ATLAS DESIGN PRINCIPLE
============================================================

Atlas should distinguish:

"I found something unusual"
from
"I have evidence that something is wrong."

"I don't currently know something"
from
"I have evidence that something is absent."

"I have a candidate classification"
from
"I have confirmed functional identity."

"I can imagine a useful inspection"
from
"The current task actually requires that inspection."

"I calculated a modification"
from
"I am authorized to execute that modification."

"A write succeeded"
from
"The resulting Blender state was independently verified."

"An answer is factually correct"
from
"The answer is complete for the user's requested task."

"Initial measured state"
from
"Final verified state."
